# 两种处理模式验证（2026-09-14，v0.9.0）

## v0.9.2：片区最高优先级取舍（2026-09-14）

用户在片区二维专项测试中要求完整块面与一二级道路优先，省略无重要作用的三级路、小碎/歪扭建筑和干扰边界的细节。图像修改后，用户认可策略并明确授权将其设为片区模式最高优先级。本条只记录策略授权，不作为 CAD/SU 验收。

修改前独立代理推演发现：旧规则要求保留可辨三级道路，未清楚覆盖“看得清但无意义的小建筑”，对保留的歪扭建筑仍倾向修整；与用户已认可策略不符。

修改后独立只读代理推演六个场景：片区过密细节、清晰公园详图、东北局部详图加区外建筑规整、桥头独立编辑、明确保留不规则博物馆与唯一窄入口、片区 urban_detail 阶段。均能按模式正确筛选，保留用户指定对象和必要例外，不扩展详图区、不以图层代替实际几何/编辑验证。代理发现独立片区模板对保留建筑规整的条件表述和首次引导旧示例存在歧义，已分别修订。

验证：既有提示词测试 26 项、处理模式测试 10 项通过；详图默认、全部场景模块、混合说明、urban_detail、design_clear 与旧无模式配置六组提示词修改前后逐字节一致。详图模板、场景模块、建筑细化和详图检查文件保持不变。修改 Markdown 的本地链接、技能格式和错例库结构检查通过。

本次仅修改技能指令和提示词输出，未更改 CAD 几何算法，未新增实际 CAD/DWG/SU 验证。单次图像策略认可不证明陌生场景有效。模式规则位于 [片区最高优先级](../references/district-priority.md)，错例适用范围见 EF012-D。

## 修改前基线

独立只读代理按旧技能模拟模糊机场城区、清晰小公园及设计清空范围三个新请求。旧开场为尺度参照、设计范围、执行路径三项，没有正式模式推荐；大片区仍允许街坊建筑组团示意重构。脚本回归测试证实 processing_mode 字段原先被拒绝，元数据没有模式字段。

## 修改后检查

独立只读代理执行五个文字场景：大片机场城区模糊输入、清晰公园直接开始、标注重新设计范围、小范围且主要路缘也模糊却要求精确详图、大范围背景＋东北公园精绘。结果分别正确采用片区/详图推荐、直接沿用已答条件、区分清空与精绘范围、明确结构证据不足，以及局部详图不外溢。模拟并非实际看图分类准确率。

代理发现详图模板的固定“低清晰度通用重构与道路退让”段落处于可替换项目条件内，运行脚本会丢失该段。新增失败测试复现后，将该段原文移至条件替换区外，内容不变，复检通过。

执行 `python -X utf8 -m unittest discover -s tests -p 'test_*prompt.py'`：26 项通过。执行 `python -X utf8 -m unittest discover -s tests -p test_processing_modes.py`：10 项通过。覆盖既有提示词/分阶段路径、模式模板和哈希记录、旧配置兼容、无效模式拒绝、局部详图区、清空版基线/范围保留、审查阶段独立及固定退让规则保留。

技能格式检查通过；修改 Markdown 的本地引用路径检查通过。CAD 几何工具未修改，因此本轮未重跑 CAD 全套测试。模式的实际生图表现、处理耗时及陌生影像分类效果留待专项测试，不以这些检查代替。
