# Map2Model 产品简介

Map2Model 是一个面向建筑、景观与规划设计师的 AI Skill，目的是让设计师从一张资料有限的场地图，尽快进入可编辑、可分面、可推拉的前期建模状态。缺少 CAD 和完整测绘资料时，设计师常要先对卫星图或航拍图描路、描河、描地块、整理建筑，再导入 SketchUp（SU）修线成面。这些重复、疲劳、耗时的工作，是本 Skill 要直接承担的部分。

已有 CAD 也可以直接上传：由 Codex 检查并整理线网，在 SketchUp 中封面，形成可编辑、可分区上色和推拉的模型；有配套卫星图或正射图时，还可结合 CAD 图层、文字和影像辅助识别道路、水体、绿地与建筑。

## 快速开始 Quickstart

上传卫星图、航拍图或已有 CAD 后，可以按资料选择入口。影像生成底图可以直接说：

```text
使用 Map2Model，把这张航拍图整理成前期建模底图，输出 DWG 和原图叠图。
```

已有 CAD 希望直接进入 SU 建模时，可以说：

```text
使用 Map2Model，把这份 CAD 整理并在 SU 中封面，输出可编辑的 SKP；结合配套卫星图，区分道路、水体和绿地。

```
独立简化平面可以这样调用：

```text
使用 Map2Model，以这张二维简化平面为主底图转 CAD；补充卫星图仅帮助识别水体和绿地，保留原有布局。
```

也可以明确用途或选择模式：

```text
这张图只作为周边背景，用片区结构模式。
```

```text
场地轮廓比较清楚，用场地详图模式，先生成二维简图。
```

Python 依赖、CAD 转换工具和 SketchUp 环境的配置与检查，请参照仓库中的 **Map2Model 安装指引**。


## 工作方式 How It Works

影像输入的首次引导依次说明**建议处理模式、尺度参照、设计范围**三项，末尾自然说明如何回复及接下来生成转 CAD 推荐稿的动作，不再询问执行路径。模式建议附具体图像依据；已经提供的条件直接沿用。不知道尺寸时可以先按相对比例，未指定设计范围时只整理现状。条件完整且用户明确要求开始时，按已有授权执行，不重复增加确认轮次。

需要简化图时，由 Codex 使用当前可用的内置生图工具生成，对照原图复核、局部修改并筛选一张转 CAD 推荐稿。完整提示词只在外部任务工作目录暂存，默认不交付；不主动引导到其他平台生成后回传。已有简化图或明确要求直接依据原图转 CAD 时，可走对应入口。已有 CAD 要求 SU 封面时，直接读取 CAD，检查断线、重线、交点和共面关系，在保留有效基线的基础上整理分区并生成 SKP；有影像时按可确认的局部对应辅助分类，叠图按资料条件选做。已有 CAD 不必先转成图片或重新生图，详见 [已有 CAD → SU 封面](references/existing-cad-to-su.md)。

内部构造先处理主路、水系和主要围合块面，再按所选模式确定需保留的内路及其接入，随后添加筛选后的建筑和必要细节。片区模式以一二级道路和完整块面为先；详图模式保留有依据的内部道路与细节。每一步都核对位置、道路连续性和边界关系，复查新增内容是否破坏已通过的外层结构。完整 CAD 任务会自主完成这些内部步骤；需要分步看成果时，可由用户提出。

影像转 CAD 时输出真实 DWG，重新读取文件核对几何，再从回读结果生成原图叠图；要求 SU 时生成并回读真实 SKP，核对实际面、孔洞及编辑组织。具体构造与验收方式见 [CAD 分面模块](references/cad-modules.md)。

## 处理模式 Output Modes

**两种处理模式决定表达深度：片区结构模式、场地详图模式。** 从影像生成底图，或从已有 CAD 整理并封面，是不同使用入口，均可采用这两种模式。

### 片区结构模式

适合大范围、细节模糊，或主要用于周边背景的底图。优先保留一二级道路、水系、完整大块分区及可信的大型或重要建筑；三级路仅保留必要连接或主要分区所需的部分。密集难辨的小建筑以有依据的片区边界概括，不逐栋补造轮廓。

片区是背景分区，不表示整片区域是一栋连体建筑。窄小但影响通行的道路和入口仍需保留。保留对象达到结构、位置和 CAD 检查要求，且概括与待补范围已有记录后即可交付，不为主动省略的小细节反复生成整图。影响结构的错误仍需修正。

### 场地详图模式

适合建筑基底、路缘、内部步道和场地轮廓较清楚，需要开展具体场地设计的图片。保留可辨的转角、院落、孔洞、真实曲线和有作用的狭窄通道，并处理倾斜投影、碎角及重复边界。

模式依据用途、覆盖范围和对象可辨程度共同判断。图片像素高不直接等于适合详图，覆盖范围大或建筑数量多也不直接等于只能概括。详图的精细程度仍以原图提供的证据为限。推荐依据与表达规则见 [处理模式](references/processing-modes.md)。

## CAD／二维简化平面为主底图时，卫星图只作辅助参考

道路、块面和建筑的位置、尺寸与布局沿用你提供的底图，补传卫星图主要帮助识别水体、绿地等区域。卫星叠图不是必交成果：有可靠对应可以叠；只有大致对应时并排参照，或明确标为“片区参考叠图，未经精确配准；不用于核验位置、尺寸”。没有卫星图或无法可靠对齐，不影响按底图转换、修线和封面。只有明确要求按影像现状校正，才在指定范围内核验后修改几何。具体见 [主底图与辅助参考](references/source-roles.md)。

## 同一张图中的分区处理

主体清楚、局部细碎时，Map2Model 会在开场第一项提出“主体详图＋局部片区概括”，指出具体区域、保留内容和表达局限，供用户确认或调整。也可以全图采用片区结构模式，仅对明确指定的局部做详图。两者都是既有两种模式的组合。

判断是否适合分区处理，要结合难辨区域的范围、分布、与实际设计范围的关系，以及它是否影响主要道路和场地结构。局部问题不自动导致全图降级；落在关键设计部位或影响主要连接时，也不能仅因面积小就省略。当前没有统一的面积百分比阈值。

例如，针对主体清楚、右下角住宅细碎的图片，可以这样说明：

> 中央建筑、道路和院落比较清楚，适合细化；右下角住宅较细碎，逐栋轮廓可能无法可靠还原。建议首轮中央按详图、右下角按片区概括，保留道路和片区边界。如果右下角也是本次设计重点，需要进一步明确保留对象，或补充更清楚的资料。你可以调整这个范围。

局部概括范围和保留对象会随提示词、CAD 对象清单及验收记录继续传递。交界处道路和边界保持接续；局部细节不足不能通过挤路、跨路并块或虚构地物解决。已有明确授权时沿用约定，不重复确认。

### 现状整理与设计范围清空

处理模式决定表达深度，成果版本决定用途。有明确设计范围时，默认先整理现状版，再派生范围内仅保留道路、其余清除为白色的清空版；范围外及未标注孔洞保留。无设计范围只制作现状版。

正式交接只主动推荐一张已复核图，另一用途版留作备选。用户选定版本后，CAD 沿用其范围与处理意图。精绘范围与清空范围分别记录，不能把要求细化的区域自动清空。具体规则见 [设计范围与成果版本](references/design-scope.md)。

## 输入分流 Input Routing

| 输入资料 | 主要处理重点 |
| --- | --- |
| 卫星图与正射图 | 保持可见位置与比例，根据用途和可辨程度决定表达深度。 |
| 倾斜航拍 | 分清屋顶、立面与地面，推定合理基底，保护道路空间。 |

| 已有 CAD，直接 SU 封面 | 检查并整理线网、闭合分面、按用途组织可编辑面组，输出 SKP；保留有效尺寸和坐标。 |

| 已有 CAD 的局部反馈 | 保留有效基线，只修改授权区域及必要邻接。 |

## 保存位置 Default Output Location

优先使用用户指定目录；未指定时，在系统实际桌面创建按场景主题和用途命名的项目文件夹。已有项目续作沿用原目录，不重复套层。

```text
场景主题项目_建模底图/
├─ 成果/
│  ├─ 场景主题_建模底图.dwg
│  └─ 场景主题_建模底图.skp
└─ 其他/
   ├─ 场景主题_二维平面.png
   └─ 场景主题_原图叠合.jpg
```

按任务提供格式：影像转 CAD 交付真实 DWG；已有 CAD → SU 主要交付真实 SKP；要求 CAD＋SU 时交付两者。最终二维图、有效用途版及有用参考图放图像参考目录；纯 CAD/SU 不强制生图。新交付的原图叠合来自最终 DWG 回读几何，不输出 CAD 与二维简图的叠图。仅影像为几何来源的任务，缺原始影像或可信配准时说明原图叠合未完成；CAD／独立二维平面为主时辅助卫星叠图选做，无影像不算缺项。

执行材料从第一次写入起就放在交付项目之外：优先使用当前 Codex 工作区的 `.map2model-work/<项目标识>/<运行ID>/`，具体选择与续跑见 [外部任务工作目录](references/output-lifecycle.md#外部任务工作目录)。提示词、旧稿、脚本及检查材料都在该目录中生成，交付项目不创建 process 或临时文件，完成后按 [文件保留与清理规则](references/output-lifecycle.md) 清理。默认不留提示词、导航说明或永久过程存档；只有用户要求保留提示词或可重跑归档时才将这些材料放入 `其他`。仅请求提示词或二维图时，交付对应成果。源资料、当前成果和指定历史稿受保护。

## 自动化工具 Automation

| 工具组 | 解决的问题 |
| --- | --- |
| 提示词合成 | 按已选模式、项目条件和场景模块生成完整提示词，记录图像与提示词来源。 |
| CAD 构造与续跑 | 按项目配方构造外层和内部对象，保存基线并处理有限邻接修正。 |
| 建筑筛查与复核 | 筛出碎角、拖尾、混杂方向等候选，再结合源图判断如何处理。 |
| 几何与分面检查 | 检查闭合、重线、路宽、图框接边及实际线网与期望面的关系。 |
| SU 默认显示 | 按已记录的本地偏好写入平行顶视、毫米、关闭粗轮廓线和开启阳光明暗，并保存回读；具体任务要求优先。 |
| DWG 回读与叠图 | 使用实际转换器保存 DWG，核对转换前后几何并生成原图叠图。 |

这些工具承担可重复的文件和几何工作；模式推荐、道路语义、建筑基底及不确定区域的取舍仍需结合源图判断。候选几何不能直接等同于已验收成果。2026-09-17 的 v0.9.11 同步核验通过 200 项既有自动测试；错例库结构与资源哈希校验通过，库版本为 0.8.3，含 14 类问题、35 个变体及 13 张代表图。本轮未重跑原生 CAD/SU 场地测试。实际验证范围见 [验证记录](evals/validation.md)。

Python 工具依赖 ezdxf、Shapely、Pillow 和 NumPy，具体以 [依赖清单](requirements.txt) 为准。真实 DWG 输出需要可用的转换软件；现有脚本支持 AutoCAD Core Console。真实 SKP 需要环境提供可用的 SketchUp 原生接口、合法 SDK 或实际导入流程；包内没有覆盖任意 CAD 的通用一键转换器。缺少转换器时保留可编辑 DXF，并说明 DWG 尚未完成。

## 使用边界 Notes

单张影像通常不能提供完整测绘信息。没有可靠尺寸时使用相对尺度；遮挡道路和建筑基底只能依据可见证据作前期推定，不能作为精确地籍、施工或法定退线依据。

生成简图看起来连通，不等于 CAD 已成面；CAD 检查通过，也不等于已经在 SketchUp 内完成导入、选面和推拉测试。各类检查分别记录实际执行范围，未执行的部分如实说明。

目前不承诺统一处理时长、固定节省比例或所有陌生图片的成功率。图像清晰度、对象密度、倾斜程度和实际工具条件都会影响工作量。主体与局部的分区取舍需要服从实际设计用途；若主要道路和片区边界本身也无法辨认，应先补充资料。
