# 处理模式：推荐、表达范围与验收

正式名称固定为 **片区结构模式**（`district_structure`）与 **场地详图模式**（`site_detail`）。用户说“场地详情模式”时理解为后者，回复仍用正式名称。两种模式决定成果表达深度，独立于输入路径（影像转底图 / 已有 CAD → SU 封面）、生图执行路径、现状/清空用途版本和 `review_stage` 审查阶段。已有 CAD 的有效详细内容不会仅因选择封面入口而被自动概括或删减；先沿用已有模式和本轮授权范围。

## 片区模式最高优先级

片区范围先执行 [完整块面与一二级道路优先](district-priority.md)，其对象取舍高于旧文及场景模块；详图和明确局部详图区不套用片区省略策略。

## 首次看图推荐

先实际查看原图的整体和有代表性的局部：道路交汇、密集建筑、大型建筑及用户关注范围。以任务用途、覆盖范围和可辨程度综合判断；放大仅帮助观察，不会创造原图没有的细节。不用固定分辨率、像素面积、建筑数量或猜测的公里数作阈值。

| 可观察情况 | 推荐与理由 |
|---|---|
| 覆盖多个街坊/大片区域，道路和大块分区可读，但小建筑多为碎点、屋面/地面边界难分 | 片区结构模式；适合先取得可用的环境与片区框架 |
| 需要具体场地设计，建筑、路缘、内部步道和主要场地轮廓可辨 | 场地详图模式；可沿用已有逐对象细化流程 |
| 主体清楚，边角建筑仍可辨基本轴向、转角或院落，但局部碎边较多 | 推荐场地详图模式，按单体或紧密小组团规整碎边并保留基本形态；不因密集直接按整街坊概括 |
| 主体清楚，局部连建筑基本形态也不可辨，且该处只作环境背景 | 可建议详图＋明确的局部片区概括；说明范围与限制，不把这项省略扩展到其余清楚建筑 |
| 场地虽小但细节仍模糊 | 不因“小范围”强推详图；结构可辨则推荐片区结构模式，并说明只能表达的部分 |
| 全图清楚但仅用于周边背景 | 可推荐片区结构模式，以实际用途控制细节量 |
| 大范围图中只有指定局部需要精绘且证据足够 | 全图采用片区结构模式＋明确的局部详图区；这不是第三种模式 |
| 连主要道路与片区边界也看不清 | 说明当前资料不足以可靠建立结构，指出需补清晰图的区域；不承诺片区模式能解决一切模糊输入 |

开场第一项输出“推荐模式＋一条具体图像依据＋主要取舍”，其后两项依次为尺度参照、设计范围，末尾自然说明回复方式与转 CAD 推荐稿的后续动作，不设路径选择。不要只让用户在两个陌生名称间盲选。例：“建议使用片区结构模式：这张图覆盖范围大，道路和大块分区较清楚，小建筑轮廓难辨；会优先保留一二级道路和完整片区，三级路仅留必要连接，小碎建筑省略。”

用户已选模式或已有项目继续时沿用其选择。新图未指定模式时提出建议；用户随后要求开始或回复“先整理全图”、未反对模式，可按建议执行并记录为“建议后执行”，不伪造明确确认。条件完整且要求直接开始时，简短说明推荐模式后执行，不新增模式确认关卡。用户偏好详图也不构成补造模糊细节的依据，应说明并记录局部表达限制。仅标注精绘范围不触发清空；仅标注设计范围不自动触发精绘，见 [设计范围](design-scope.md)。

## 主体清楚、局部细碎时的开场说明

这种情况在首次引导第一项主动说明分区处理建议：指出哪些区域适合详图、哪些区域只能可靠概括、局部可能无法还原什么，以及建议先如何处理。只将此说明用于实际存在清晰度/可辨程度差异的图片，不在每张图上追加固定提醒。

例如：“建议采用场地详图模式：中央场地和主要建筑比较清楚；边角小楼虽然碎，但仍能辨认基本转角和院落，会保留单体或小组团、规整碎边。完全遮挡且只能作背景的部分另行概括。”位置和对象必须来自当前原图，不能把‘中央/右下角’套用于其他图片。

单体或小组团的碎边规整仍属于详图；只有明确采用局部片区表达时才是两种模式在不同区域的组合，不新增第三种模式、不增加第五项。初次条件引导时让用户在同一轮确认或调整；用户确认该建议后沿用，不再次询问。已有完整条件且明确要求直接执行时，简短说明分区处理后按既有授权推进；只在关键范围歧义会改变成果时澄清，不额外设置强制审核轮次。

判断主体是否能细化，重在建筑基底、主要道路、院落和场地轮廓的可辨程度。覆盖范围大、对象数量多或局部工作量大，本身不足以把全图降为片区结构模式。树冠省略能减少纹理干扰，不能恢复被遮挡的地面证据。

执行时，主体详图用 `processing_mode: site_detail`；在现有 `notes` 中明确局部概括范围、可辨道路/片区保留要求、难辨单体省略及限制，必要时在 `omit` 中限定对应对象，不新增脚本不支持的配置字段。明确采用局部片区表达的区域执行本页片区合同；详图内仅做碎边概括的区域继续保留可辨建筑基本形态，实际道路和清楚建筑仍保留，背景片区不冒充整栋建筑。范围以可辨道路或街坊等边界描述；有实际意义的歧义才补问，不自行圈成设计清空范围。

将同一分区取舍传入生图提示词、CAD 对象清单及验收记录；交界道路、宽度与共边保持连续，不输出拼接缝。首轮按约定分区处理，局部结果仍不可靠时保守概括并记录待补，不为补小单体反复整图生成。若用户拒绝概括、希望该局部也精绘，按其意图核对证据并说明需补清晰资料的部分，不暗中降级，也不承诺恢复不可见细节。

## 表达合同

**片区结构模式：**

- 最高优先级成果是完整父块、一二级道路与主要水系。三级道路、园路及内部支路默认省略，仅保留必要连接或决定主要分区的例外，并记录作用；按空间作用判断，不误删承担骨架作用的窄路，也不臆定法定等级。
- 保留主要水系、完整绿地/硬地/场地外围。建筑先筛选，仅留有意义且规整的大型建筑或规则排列；真实弧形、L/U形与院落保留。无重要作用的小碎、歪扭建筑，以及靠近边界易干扰且不规整的建筑直接舍弃，不为保楼缩路移块。重要且规整的真实贴街楼按共边处理，不自动删除。
- 小碎建筑不因能辨认就必须保留；不重要的单体直接省略，密集不可辨区不逐栋描画，不补造若干象征性“小房子”。以路缘、围墙、明确用地变化等有依据边界概括街坊/片区，保留必要的空地与通道。片区是背景分区，不代表连体建筑，不能虚构地籍线。
- 图像中未展开片区用中性背景，实际建筑才用建筑色。CAD 的片区边界/面在过程清单中记录为 `context_block` 角色并与建筑分层（如 `CONTEXT_BLOCK`）；不得进入建筑清单、逐栋复核或建筑推拉高度规则。此语义记录不作为未经支持的新字段注入 CAD 检查或构造配置，脚本配置沿用其支持的地块/背景角色。与道路及相邻面共边只导出一条有效边，必要语义对应放过程记录，不叠画重线。
- 不绘车辆、停车格、纹样、零散树冠和不影响结构的微小设施。源侧清单先记录保留、概括、省略/待人工补充区域，再生成或构造；不能为了让失败检查通过才事后改成省略。

**场地详图模式：**

沿用已有效的建筑平面化、内部道路、绿地及场地细节检查流程，保留可辨的转角、L/U 形、翼部、院落、孔洞和有作用的狭窄通道。局部模糊碎边按 [单体或紧密小组团](building-regularization.md#详图的单体保留与小范围概括) 规整，保留可辨基本样式，不用街坊外缘替代整片建筑；画幅大小与密集程度本身不构成删楼依据。详图的精度上限仍由源图决定；局部证据不足时概括或记录待补，不全图降级，也不以生成的精致轮廓代替原图依据。

用户明确的局部详图区记录 `detail_scope` 及授权依据，片区模式仅在该范围执行详图规则，范围外继续概括。局部详图区与设计清空范围可重叠，但清空版范围内仅留道路的用途规则优先。

## 从提示词到交付

新项目在生图或直接 CAD 前记录 `processing_mode`、`mode_reason`、选择依据（用户指定/建议后执行）、局部详图区及取舍清单。使用 `build_prompt.py` 时填写已选模式；脚本仅据字段选模板，不自动识别清晰度或代替 Agent 推荐。片区模式默认使用完整的 `district-structure.txt`，不是只画主路的临时 `urban_structure` 阶段稿；默认仍 `review_stage=complete`。详图沿用 `simplify-map.txt`。场景模块只强化当前表达范围，不把片区模式重新升级为逐栋重构。

两种模式均保留原图位置、道路连续与宽度、唯一共边、闭合/完整分面、DWG 回读及原图叠图要求。建筑检查覆盖所有实际保留建筑；已按片区概括的小建筑不要求逐栋清单或逐栋图像门。完整线网仍覆盖所有片区，不能靠改图层绕过拓扑检查。

**片区模式停止细化的条件：** 一二级道路及例外保留道路接续可靠，主要片区/水系/大型对象位置和关系通过复核，实际 CAD 检查与文件回读通过，概括及待人工补充范围有记录，即进入交付。已决定省略的三级路、小碎建筑及细节不因“不像人工逐栋描图”重新进入返修队列；不反复全图生图追求同等细致程度。结构错误仍须修复，关键结构缺证据仍如实列出。详图继续按可辨对象及既定合同验收。未运行原生 SU 测试不得声称已在 SU 选面/推拉通过。

## 人工标注样本校准

用户批量提供图片用于分类测试时，先逐图给出建议模式和可见依据，再接受用户标签，记录文件名/哈希、用途、Agent 推荐、用户确认、分歧原因及局部例外。仅做分类测试不启动二十张生图或 CAD。将错分原因归纳为可观察的判断规则，经用户反馈更新，不把单张图的尺度或像素参数推广为统一阈值，不宣称自动训练了模型。尚未提供/确认的样本不能记为通过。
