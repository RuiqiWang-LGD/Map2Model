# 建筑细化：主体判断与异常轮廓规整

当前表达范围先按 [两种处理模式](processing-modes.md) 确定。片区结构模式中难辨密集小建筑只保留有依据的背景片区边界，不逐栋或按象征性建筑组团重构；实际保留建筑继续本页检查。下文细节/逐栋规则适用于场地详图模式、授权局部详图区或片区模式实际保留对象，不重新扩大对象清单。




适用于简化图中的“建筑”呈现夸张碎折线、细长尾巴、薄连接、被铺装牵连的外轮廓，或用户指出楼体应比当前块面更规矩的情况。仅中小尺度场地详图在图像阶段先执行下方二维基底门；大尺度沿用分区和组团处理，不套用此新增逐栋门；进入 CAD 后，它在**一级道路 → 围合块面 → 二三级道路**确定后执行建筑细化，属于 [CAD 分面模块](cad-modules.md) 的 M2 内部步骤，M1 外层先通过。不能把 CAD 顺序理解为生图阶段可以保留明显伪立面。



低清晰度对象先按 [通用重构与道路退让](low-clarity-reconstruction.md) 选择示意程度并预留道路空间；这与大/中小场地尺度分别判断。小场地中难以逐栋辨认的区域不强行逐栋还原，清晰对象仍按下述规则处理。

## 中小尺度建筑的二维基底门



场地范围适中、建筑数量与清晰程度允许逐栋处理时，优先逐栋修正，不以小场地为理由降低要求，也不设置脱离图像证据的固定栋数阈值。此门从推荐二维简图前开始，进入 CAD 后继续复检；此门仅适用于中小尺度场地详图，大尺度无论建筑是否稀疏，都沿用原有道路优先、分区和组团方法，不新增全图逐栋图像验收要求。大尺度中用户明确指定的局部详图区可单独采用此门，不把该要求外溢到整张图。依据是场地尺度和任务用途，不是像素大小或放大后的可见程度。



1. 对全部可辨建筑建立简短对象清单，逐栋分清屋顶边、立面投影、接地边和相邻人行空间。允许接地边有推定，必须与已识别路缘、院落和通道相容。

2. 以接地位置和该栋轴向重建单一二维占地外环，清除屋顶—基底双轮廓、立面窄条、檐口平行线、斜连接线及高度拉长的外包络。删除线条后仍然错位或拉长，继续改轮廓；不能只去纹理、换浅灰或把实体 Z 设为 0。

3. 保留真实 L/U 形、凹口、组合翼部、院落和有依据的独立单体，不统一缩楼或强制矩形化；局部修正冻结正确路网及未受影响的地物。

4. 在足以辨认建筑边缘的局部视图逐栋检查，再看全图道路与接边。每栋记录保留/修正/待查及源图依据。伪立面或明显基底偏移仍存在时，该版本不得标为推荐稿；有可用生图编辑能力时局部修图后复核，不为小区域错误反复全图重生。



源图证据不足时可用简洁、位置合理的推定基底并说明推定；这不同于继续沿用可见立面投影。工具修正仍失败或关键接地证据缺失时，交付候选并简短指出未解决区域，保留过程，待用户明确接受带限制转换后再推进，不能宣称建筑已通过。本门不承诺生成模型每次都能修好。




## 阴影穿过建筑时的类别复核（EF005-D）

触发：建筑外环恰在明暗交界处终止、同向屋面/檐口在阴影两侧疑似连续，或用户指出漏掉建筑范围。先跨越明暗区追踪屋面结构、檐口和墙体轴向，再用接地边、院落和相邻通道确定占地；同时排查建筑被漏判为铺装与铺装被误并为建筑。阴影边本身不构成类别或占地边界。

记录四项：亮部和暗部的结构联系、可见/推定接地边、受影响邻接通道、修订后覆盖及旧分界清除结果。有结构连续依据时补回漏识别部分并重建单一外环；仅有投影而无建筑结构依据时保留地面。用户近似批注用于确定本轮修订意图，按地面关系规整，不复制手绘抖动或把其作为通用尺寸。

手绘批注只表达目标对象与大致范围，连大尺度弯折、斜角也不能直接当成真实形体；以原图主要轴向、直墙、曲线或真实转角重建。原图支持直墙则拉直，支持真实曲线或凹口则保留，不一律矩形化。

修复仅作用于该建筑及必要邻接，回查主路、父块和内部通路。中级/大尺度保持原处理尺度，不因此全图逐栋精修。阴影成因若只由用户或代理推测，分别记录事实与假设；局部图像修复不等于陌生场景识别或CAD/SU已验证。案例见 [EF005-D](error-library/cases/EF005.md#ef005-d--阴影下建筑被漏判为铺装)。

## 先判断是否需要动



| 情况 | 动作 |

|---|---|

| 已有清楚矩形、L/U 形或方向一致的正常楼体，小凹凸不影响使用 | 保留；不追求全图统一方正 |

| 很多短边、无结构规律的斜边/耳朵/尾巴、多个体量疑似被窄带串起 | 列为源图核对候选；几何分数本身不能决定修改 |

| 卫星图可见连续屋面、檐口或重复结构方向，异常边落到台阶、铺装、道路、树影 | 重判建筑主体与地面，把地面部分从建筑类别分离 |

| 弧形大屋面、真实斜翼、分叉组合楼或合理的内院 | 保留实际结构；复杂不等于错误 |

| 屋面/平台或薄连接在源图无法分清 | 保留最少推定并记录不确定性，不自动删除连接或强制填矩形 |



灰白区域不一定是建筑，规矩矩形也可能是停车场、运动场或铺装。因此，即使没有几何异常，初次类别判断仍需结合源图；可疑清单用于集中复核，不能替代语义识别。



## 按建筑自身结构重建



1. 固定已通过的外层、父块 ID、路网和本轮改动范围。继承用户对二三级道路等对象的取舍；用户说本轮留给人工，则本轮不重建这些道路，不把该选择写成所有项目的省略规则。

2. 对照原始影像，分清屋面主体、疑似有盖连廊、无盖铺装、台阶、院落、阴影与屋顶设备。真正铺装留为地面；可用已有父块/内部场地剩余面表达，不必另造紧贴建筑的一圈线。

3. 从可见长屋面边、重复轴线估计**该栋/该组建筑**的方向。用少量矩形或正交多边形组合拟合主要翼部，整理零碎斜角；保留有依据的 L/U 形、凹口、斜翼和曲线。不能用统一世界XY轴，不能将整个复杂外包络替换成一个最小包围矩形。

4. 原先由无盖地面串联的单体，拆成独立建筑环；有盖连接仍保留。真正屋面组团按连接关系保留为一栋或多个明确单体。局部删除/新增对象须记录前后 ID 对应，避免把漏楼解释成简化。

5. 原生闭合环输出，Z与单位沿用。重建建筑应放在本父块内；必要的小幅同侧平移有源图精度依据并记入日志。不能为了保护旧图而把楼推到明显错误位置；实质外围冲突回到 M1 按授权修复。

6. 建筑改动造成相邻绿地接触/穿越时，只修该处接边。既有庭院保持合法嵌套，重要绿地不能整块丢弃；移出的铺装区域按真实地面表达。复检同父块其他对象，再对完整图执行闭合、面对应、道路基线与 DWG 回读检查。



把“几何拟合”和“语义修正”分别记账：单纯拉直/减点按项目的面积对称差、最大边界偏移与通道保护阈值检查；把铺装剥离、拆楼或纠正错误类别可能大幅改变旧 CAD 面积，应记录源图依据及前后形体，不虚称仍在原 3%–5% 拟合误差内。阈值不能代替判断，也不能通过放大容差来掩盖断路或越界。



## 可执行的半自动环节



使用只读的 `scripts/triage_buildings.py` 批量产生可疑建筑清单：多转角、短边比例和混杂方向用于排序。它不改 CAD，不从照片识别屋面，不自动重建建筑。被列出可能只是合理的组合楼；没列出也不表示类别或位置正确。几何描述中的主方向来自当前 CAD，重建时仍要从源图确认轴向。



```text

python "<Skill绝对目录>/scripts/triage_buildings.py" work/process/current.dxf --manifest work/process/detail-manifest.json --config work/building-triage.json --report work/process/building-review-candidates.json

```



清单是含 `id, handle, role` 的对象数组，可额外保留 `parent, source` 等字段；脚本仅检查 `role` 以 `BUILDING` 开头的原生闭合无 bulge 多边形。角色与清单必须覆盖本次想审查的全部建筑，不能只列已知异常再宣称全图已筛查。原生曲线、开放或异常实体列为 `geometry_deferred`，不偷偷弦化，也不直接判错删掉。



复制 [参数示例](../examples/building-triage.json) 并按本项目尺度配置：



- `min_vertices`：转角多时提请核对的顶点数，示例仅演示配置。

- `short_edge`：短边判断长度，**绘图单位**；不是通用像素阈值。`short_fraction`：短边占所有边的比例。

- `axis_angle_degrees`：相对本对象两组垂直方向的角度容差；`off_axis_fraction`：超出该角度范围的边长占总周长的比例。



报告逐对象给出 `review_candidate / no_geometry_trigger / geometry_deferred`、理由、度量及绘图坐标范围，并固定 DXF/配置/清单哈希。`automatic_edits` 始终为0。返回码0表示完成了清单范围的筛选，1表示有无法检查的实体，2表示输入/配置错误；都不是 CAD 验收结论。报告拒绝覆盖输入及其链接别名，默认也不覆盖旧报告。



在项目的 `building_decisions.json` 记录每个候选和用户指定对象的 `id, decision, evidence, confidence, changed_handles, validation`；`decision` 可为 `keep / regularize / separate_ground / defer`。确认屋面后优先使用 [CAD 自动执行](cad-automation.md) 的通用形体配方按轴向/组合体构造，有限处理受影响绿地，再自动运行完整图检查与前后复核页。坐标、像素值、具体 ID 留在项目配置，不进入通用规则。



当前自动化范围是“筛选、几何构造、回归检查”；建筑与铺装的类别判断仍由 Agent 对照源图完成。该判断不必每次交给用户逐栋确认；在已授权范围内，有清楚证据即可执行，不清楚时按影响记录待查或只询问关键缺项。未来接入影像识别也应保留这些判断与回归门槛，不能把几何复杂度当成语义置信度。



## 完整覆盖门（EF002 / EF005）



见 [建筑异常错例](error-library/cases/EF005.md) 及 [覆盖遗漏](error-library/cases/EF002.md)。即使道路/封面通过，也必须完成应保留建筑的形态检查。先按街坊建立完整清单，包含曲线、共边和暂不能自动识别的建筑；与实际 CAD 及源图逐街坊核对清单覆盖。小建筑不是免检项。



当前版本的 triage.objects 必须覆盖清单全部建筑，不能只喂已知异常。每项有 keep / regularize / separate_ground / defer；正常对象可共用本街坊的源图复核证据，不能仅因 no_geometry_trigger 就写已视觉通过。几何工具不能识别的对象用等效检查并记录实际理由；defer 不算通过。



最终输出前运行：



```text

python "<Skill绝对目录>/scripts/check_building_review.py" work/process/final-roundtrip.dxf --manifest work/process/building-manifest.json --triage work/process/building-triage.json --decisions work/process/building-decisions.json --report work/process/building-coverage.json

```



manifest 为含 id、role 的完整对象数组；沿用 triage_buildings 输出。decisions 使用 `{"dxf_sha256":"当前回读文件哈希","objects":[{"id":"对象ID","decision":"keep","evidence":"实际源图复核记录","validation":"本版检查依据"}]}`。旧列表需先核对实际版本再绑定，不直接填新哈希迁移旧结论。数量、ID、版本必须一致；已拆楼同步新单体 ID。未运行或仍有待查项就不能声称完成建筑验收。脚本只核对声明清单与记录，不自动证明源图漏楼或视觉判断正确。
