# CAD 执行路径

**先按 [主底图与辅助参考](source-roles.md) 确定几何基线。** 本页“原图／源图”按资料角色理解：独立上传的 CAD 或二维简化平面作为主底图时，位置、尺寸、轮廓和连接以该底图为依据，补充影像只辅助分类；下文要求按影像重建基底、修正位置和做原图叠图的条款，仅用于影像作为几何来源或用户明确授权按影像校正的范围。资料角色规则优先于本页通用措辞。

**片区模式优先入口：** 片区范围先执行 [完整块面与一二级道路最高优先级规则](district-priority.md)，再应用下文于实际保留对象；下文“二三级道路/内路/全部建筑”不扩大片区保留清单。场地详图模式及明确局部详图区保持原细节规则。

当前表达范围先按 [两种处理模式](processing-modes.md) 确定。片区结构模式中难辨密集小建筑只保留有依据的背景片区边界，不逐栋或按象征性建筑组团重构；实际保留建筑继续本页检查。下文细节/逐栋规则适用于场地详图模式、授权局部详图区或片区模式实际保留对象，不重新扩大对象清单。


复杂城市及低清晰度场景按 [结构优先与按需分步](complex-urban-two-stage.md) 执行。直接 CAD 默认自主构造并核验道路/河道桥梁/父块基线，再添加二三级道路和内部细节，完整复检后一次交付，不预设外层必须用户通过。只有用户明确要求分步或关键结构经自查仍需用户决定时才交阶段/局部证据。栅格或既有 CAD 的通过记录按原版本保留，CAD 外层仍以原图核验；实际错误自主局部修复，涉及改变用户已确认意图时再请求决定。

## 先判定处理入口

独立二维简化平面转 CAD：以该图轮廓、相对比例、标注及路网为基线；有辅助影像时按 [资料角色规则](source-roles.md) 分类，不强制重新生图、套卫星位置或补交卫星叠图。已知由本任务影像生成的中间简图仍继承原影像定位关卡。

已有 CAD 要求 SU 封面或结合影像分类时，先读 [已有 CAD → SU 封面](existing-cad-to-su.md)，跳过生图入口。已有可信 CAD 的单位、尺寸和几何基线按该入口保护；影像用于辅助识别与发现冲突，不能仅因影像较模糊或错位就重绘 CAD。

先按 [设计范围与成果版本](design-scope.md) 读取用户选定版本。清空版中范围内非道路对象的删除是设计处理，不是漏识别；原图只校核保留道路、范围边界和范围外内容，不把已清除对象恢复。

先继承 [图像交接](image-stage.md#交接到-cad) 的实际选择：内置图须完成选图确认；用户已明确指定图并要求转换即为授权。外部回传/导入图在用户要求转换时直接执行；用户拒绝可选改进时按当前图转换，记录被拒绝的改动，不误当作取消 CAD。

新场地没有已验收CAD：先按第一阶段检查原图/分析图并建立源图锚点、道路连接和主要外围清单；直接从原图做CAD时也采用相同判断。不借用其他项目基线、坐标或尺寸。

更新已有CAD：另存副本，记录用户本轮范围、已接受几何和允许改动对象。将新分析图用于未解决的关系，不重新矢量化整张图覆盖旧成果。旧对象若被用户指出错，局部更新它的依据与验收状态。

读取源图时保存原分辨率。记录像素到CAD的变换，明确坐标单位，比例来源和设计范围。已知尺度通过可辨对象落地；投影畸变大的区域按地面证据局部判读，不让全局形变同时拖动正确道路和建筑。

中小尺度及已授权局部详图区先按 [细节检查](site-detail-checks.md) 登记绿地地面边与每条内部步道的独立源侧期望，构造后核对实际边链与面；推荐图、CAD 导出和最终回读分别记录状态。

## 分对象构造实际几何

**默认先读 [SU 前期平面合同](su-plan-contract.md)；路网清楚、色块围合明显的图再读 [CAD 分面模块](cad-modules.md)。** 构造前保存源侧期望对象、道路同面组/探针、唯一水陆边界和简化预算。下列顺序分两次落实：外层步骤只建立主路、水域、父块外环和图框接边，通过完整原始线网与源侧面对应检查后保存基线；内部步骤加入建筑/场地等子环，再对完整图重查道路与父环。默认在同一任务自主完成两个内部步骤，不为复杂程度、模糊程度或模块边界额外索要批准。仅用户明确要求逐步看成果时按约定交接外层；关键结构经自查仍不明确时仅请求所需的结构决定。

1. **道路**：确定节点与必要连接，按可见中轴趋势和路宽构造边界。直段保直，推定弯段用平顺骨架与近似等宽偏移；同层连续道路和路口合为可独立选面的区域，删除横向封口边。保留真实分隔绿带。桥面/主路占地裁除内部低优先线，再整理共享边与实际节点；现实跨层关系不按同层路口硬连。
2. **水陆、高差、地块**：先定有使用作用的大分区，再描有依据的外围。默认水陆界只留一条有意义的边，无独立用途的窄岸带并入相邻大面；详细岸顶岸脚按用户明确请求另行表达。确定主平台/场地外围、入口和图框截边；不要引入临时闭合斜线。将主要外围列为必导对象。
3. **建筑**：按区域分清可见单体、密集低层、倾斜投影、遮挡及棚架。按接地依据重新估计偏移基底，保护道路；中小尺度且可逐栋处理时，对全部可辨建筑执行 [二维基底门](building-regularization.md#中小尺度建筑的二维基底门)，轻度屋顶偏移、沿街侧墙窄条和双轮廓也检查，不仅处理严重投影。检查裁切残片，避免只把占路部分切掉就接受剩余窄条。同街坊合并时保留通道/院落孔洞。出现夸张碎折线、细长尾巴或地面串联时，进入 [建筑细化](building-regularization.md)：筛候选、核对屋面与铺装、按自身方向规整；正常及合理复杂轮廓保留。
4. **设计范围内部**：现状整理版画清楚的大块和有作用小块；清空版仅保留道路及留白分面，不加入非道路子环；明确半圆/圆弧可用 ARC 或 LWPOLYLINE bulge。密集环境区用较少顶点概括，重点地块提高贴合要求，不套全图统一简化值。
5. **整理拓扑**：可见平面全部边界的交点落实为实际端点，共享边只保留一次，近端点在有依据范围内吸附，检查真实面环和孔洞。详细高差参考另存，不混入默认选面平面。保留语义面清单供索引与相交检查；另用独立源侧期望检验真实完整线网，语义清单不替代实际面。

自动工具的候选不能直接跳过上面步骤。对象关系和形体已明确时，优先用 [CAD 自动执行](cad-automation.md) 的通用构造配方、复核页与阶段续跑；坐标/选择器属于项目过程。工具范围外再编写本项目几何脚本，保留同等检查；修正原则来自共用规则。

## 辅助矢量化：生成候选

```text
python "<Skill绝对目录>/scripts/vectorize_plan.py" --input work/class-mask.png --output-prefix work/process/candidate
```

适用已验收纯色分析图或经纠正的分类mask，不能直接对原始照片使用。默认精确匹配palette；不符合的像素会明确报错，需先修正分类或按CLI提供的受控容差处理。道路颜色的细描边仍可能被误当道路，这必须语义检查，不能声称颜色分割已理解场地。

输出候选DXF、含真实孔洞的本地平面GeoJSON及尺寸/变换metadata。默认像素相对坐标、INSUNITS=0。有尺度时显式提供 `--units m --units-per-pixel 数值` 或 `mm`，不要把“1px=1m”当默认。

候选保留面环，跨类共边可能重复，曲线还可能是像素折线；metadata标记draft。后续按上述道路骨架/实体边界规则拟合及共享边整理，不能把这个候选直接冒充最终成品。面积过滤默认不开启，避免吞掉有作用的小对象。

需要更平滑轮廓可设置 `--simplify-px`，但先检查局部通道和相邻共边。该参数不是形体通过门；持续台阶、交替短转角和碎面须按对象方向/曲率进一步规整并量测偏差。没有“对所有建筑统一简化/缩小”的隐藏步骤。

## 几何与空间检查

根据 [项目设置](project-contract.md) 填写项目配置：

```text
python "<Skill绝对目录>/scripts/check_cad.py" work/process/corrected.dxf --project work/project.json --report work/process/qa.json
```

脚本只读DXF，默认未满足视觉证据会返回非零。处理每条失败/待查项，记录局部修复，再运行当前文件的检查。原图叠图逐区看主次路、桥头、岸边、高层基底、密集路网和主要场地外围；不能只看全图缩略图。

代码中已定义的平台不代表导出存在。实际导出后填required_handles/关联边链；必要的孔洞使用hole_map确认语义。若CAD道路边线不构成独立封闭道路面，road layer不要误配置为面层；将独立语义道路面验证另存证据，明确该脚本road检查not_run，仍判读道路连通。对于要求独立分面的任务，not_run 不免除路网成面要求：独立环用分面模块检查器从实际全图恢复道路，其他表示须补充等效面对应检查。

## 真正导出 DWG 并回读

有 AutoCAD Core Console 时使用本机明确可用的路径，例：

```powershell
powershell -NoProfile -File "<Skill绝对目录>/scripts/export_dwg.ps1" -InputDxf work/process/corrected.dxf -OutputDwg work/final.dwg -RoundTripDxf work/process/final-roundtrip.dxf -CoreConsolePath "本机实际的accoreconsole.exe完整路径"
```

脚本默认拒绝覆盖，输出真实R2018/AC1032 DWG，再打开该DWG并导出回读DXF，保存转换日志和哈希。转换器位置没有默认本机路径。使用ASCII临时目录是脚本的AutoCAD兼容条件，中文最终文件路径通过暂存复制支持。非Windows或没有AutoCAD，可使用其他合法转换器，但同样留回读证据；不要自动下载安装收费软件。

回读后比较：

```text
python "<Skill绝对目录>/scripts/compare_dxf.py" work/process/corrected.dxf work/process/final-roundtrip.dxf --report work/process/roundtrip.json
```

再对回读DXF运行check_cad、适用的分面模块与 `check_visible_plan.py`（携带同一独立源侧合同），完成 SU 前期平面合同各门并更新关联视觉证据。转换器AUDIT若修掉了实体，几何对比应报差异；逐项确认，不默认放行。没有可用转换器时保留DXF候选，清楚说明DWG未完成，不修改后缀。

## 叠图与最终交付

以影像为几何来源转 CAD 时，默认将真实 DWG 放入 `成果`，卫星/正射原图叠图 JPG 和最终二维平面放入 `其他`。独立二维简化平面转 CAD 交付真实 DWG；以 CAD／独立平面为主时，卫星叠图按 [对应程度](source-roles.md) 选做，无影像不算缺项。已有 CAD → SU 封面主要交付 SKP；用户请求 CAD＋SU 时同步交付 DWG 与 SKP，执行 [对应入口](existing-cad-to-su.md) 的文件回读要求。取消二维简图叠图；不为它运行渲染，也不把检查报告、说明或 metadata 交付给用户。选图阶段二维平面图不受影响。

```text
python "<Skill绝对目录>/scripts/render_overlay.py" --dxf work/process/final-roundtrip.dxf --source work/original.jpg --transform work/process/original-transform.json --output work/process/final-original-overlay.jpg --source-kind original
```

渲染和转换先在 process 中完成，metadata/日志在执行和复检期间保留；验收后将当前 DWG/SKP（按任务范围）放入成果目录，将最终二维图和原图叠合放入图像参考目录并核对。待所请求任务最终验收、保存核对完成后，按 [文件保留与清理](output-lifecycle.md) 清理无依赖的提示词、旧稿与临时过程文件，默认不另建永久追溯记录包；候选输出或仍需续跑不触发清理。旧交付不自动删除或覆盖，局部修订使用新版本名或新目录。

原图叠图核对保留道路、地块和范围外建筑；清空版已授权删除的非道路对象不算漏绘。必须采用最终 DWG 回读 DXF，检查 metadata 的 dxf_sha256、source_kind=original、原图和变换哈希。全图与高风险区域分别看图，禁止仅用全图缩略图验收。

沿用可追溯配准；缺少配准则按源图对应建立并用独立对象复核。不得 fit 当前 CAD 包围盒或局部扭曲来掩盖偏差。细节见 [项目设置](project-contract.md#叠图变换)。仅以影像为几何来源的任务，缺少原始影像或可信配准时，继续可独立完成的 CAD 工作并说明原图叠图未完成，不以简图、生成图或重命名文件代替，也不跳过未通过的定位关卡。CAD／独立平面为主且影像仅辅助时，不适用此待补要求；大致参考叠图按资料角色规则标注，不能作定位验收证据。

可编辑、可分面是构造目标；未运行 SU 不宣称 SU 软件内已验收。


## 道路边界冲突的优先处理

以下影像位置审核仅用于影像为几何来源或用户授权影像校正的范围；CAD／独立二维平面为主底图时，按 [资料角色规则](source-roles.md) 检查主底图，辅助影像冲突不触发自动改线。

现状底图的道路、分隔带、地块外缘及入口位置，以原始卫星/正射/航拍中可辨认的地面边界为首要依据；生成二维图只帮助理解结构与分类。用户认可简图或说“按此图转 CAD”，不等于授权沿用与原图冲突的位置、宽度或轮廓。只有用户明确要求设计改线或明确放弃原图定位时才改变该约束，并单独记录。
发现冲突先核对对象是车行道路缘、人行道外缘还是绿地内缘，不能混用。独立验收点、横断面、转弯位置和入口须取自原图；不得只检查与生成图的重合度、以生成坐标作为期望，再用几何闭合/回读一致证明定位正确。树下遮挡短段另记推定依据。
一级道路与父块外边界的原图位置审核具有阻断优先级：先查看实际 CAD 在原图上的叠图，并复核关键边界和宽度。出现明显冲突即将该区域及依赖细节置为未通过，完成原图边界修正后才推进内部细节；不能仅披露“存在偏移”后继续交付。用户指出边界问题时，先重新检查证据基准，不能只提高对错误简图的描摹精度。原图叠图不是可有可无的展示附件。

原图边界和依赖细节分开保存状态。用户正在审查外层修正时，只提交明确标注的道路/父块边界审查成果，不把尚未重新定位的旧内部对象挂回并称完整修正版。


## 构造与验收的补充经验

同用途对象的新增细分必须有来源与用途；依 [细节检查](site-detail-checks.md#同类反馈的优先检查) 审查隔离带内圈和花池主形。构造布尔交点过早舍入可能产生微小差面、短边和失配；保持足够计算精度、统一共享接点，输出精度按项目单位和误差预算确定。不得套用固定小数位或在检查时修复临时线网来制造通过。

源侧探针误置时重新查看原图，保留旧错误期望及纠正理由，不能为了适配待检几何移动探针。完整线网、原图语义/形态、DWG 回读和用户验收分别记录。
