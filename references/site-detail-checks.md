# 中小尺度绿地与内部步道检查

适用：中小尺度现状详图，以及用户已授权的大尺度图内局部详图区。按覆盖范围、用途和对象可辨程度写 `scale_reason`，继承项目既定方法；高像素或放大不触发全图精修。大尺度其余区域继续道路、分区、父块和街坊组团方法。设计范围清空版只检查保留道路、范围接边及范围外对象，不恢复已授权清除的绿地。

进入详图检查前，先按 [分级围合与规则几何](hierarchy-and-regular-geometry.md) 固定一级道路与父块基线，再处理内部步道。规则圆角、绿地/停车条带的端部与共边为高风险位置；有依据的规整优先于碎像素贴合。道路可提取和相邻块面独立是两项检查，不能互代。

## 逐对象记录

在现有对象清单上补充以下记录（可另存项目 `detail-checks.json`，用 `object_id` 对应清单 `id`），不用另起一份脱节的对象表。推荐图前记录源侧判断；CAD 构造前确定独立期望，导出及最终回读后填写实际观察值与映射。未知写 pending 或 not_run，并说明原因。

| 必填字段 | 内容 |
|---|---|
| `object_id`, `role` | 本图稳定对象 ID；绿地/花池或内部步道，步道按节点到节点分段 |
| `parent_id`, `road_class`, `expected_relation` | 对应父块；道路注明层级，用源侧依据说明与接入对象同面或异面，非道路层级字段可为空 |
| `scale_reason` | 本对象适用详图门的依据与授权范围 |
| `source_view` | 未标注原图的项目引用、版本/哈希、局部视窗及变换；批注另存为意图材料 |
| `ground_evidence` | 逐边/段的可见池壁、路缘、铺装—土壤交界或通行接入证据 |
| `occlusion_and_inference` | 可见段与遮挡段分开；推断所用相邻端点、走向、宽度或地面接触关系及未能确认之处 |
| `independent_checks` | 每项包含 `check_id`, `segment_or_feature`, `source_basis`, `expected`, `observed`, `status`；量测另记单位、项目容差与依据，expected 先于待检 CAD 建立 |
| `cad_mapping` | 本版实际导出文件/哈希、图层/handle 或边链与恢复面 ID；用面索引时核实它与实际完整线网对应 |
| `visual_status`, `geometry_status`, `open_issues` | 分别记录结果、版本、证据引用；未执行及剩余推断不能自动填 pass |

`independent_checks` 按下表展开，不用一句“已检查细节”覆盖全部对象。每条应保留步道、每块应保留绿地都登记；缺项、版本不匹配或未处置失败时，该对象检查未完成。源图确实不能判断的项目保留 pending/推断；用户接受限制另记 accepted_limitation，不改变测量结果。

## 绿地：检查地面外缘

| 检查项 | 源侧期望与实际观察 |
|---|---|
| 实体边与重要转折 | 沿可见池壁、路缘或铺装—土壤交界定位；冠幅扩大、树影或屋顶投影本身不改变地面占地 |
| 楔形尖端与狭窄段 | 单独记录端点、内外侧证据和邻接对象；局部窄也不能漏掉或被平滑吞没 |
| 遮挡续接 | 用可见两端、邻接铺装/道路及有依据的接地边作最少推断；分开标明可见边与推断边 |

可用独立边界点偏差、内外点归属、边链连续性检查几何；仍需对照原图看转折、尖端和遮挡处。常见花池形式只可作为候选解释，不能替代现场证据；没有可见依据时不能把矩形、圆形或沿建筑退线当标准答案。特定方位和案例轮廓不迁移到下一张图。

## 内部步道：双侧、宽度、转弯、两端

| 检查项 | 源侧期望与实际观察 |
|---|---|
| 双侧边 | 每段两侧分别选原图证据点/边段并对应 CAD 边链；仅中线或单侧贴合不足 |
| 法向宽度 | 在可辨直段及宽度变化处，按该段自身轴向作法向断面，比较可用路面宽度；两条路独立判读，不强制全长共线或套同一宽度 |
| 弯段 | 核对转入/转出位置、两侧曲率或真实折角、弯内净宽；平顺拟合仍须保留现场有依据的转折 |
| 两端入口/平台接续 | 从起点追到终点；分别登记接入对象、开口宽度和同面关系。对源图与用户选面目标确认属于同一建模路面的接续检查同面探针与入口横向干扰线；道路/平台用途分界另查异面与唯一共边，不能只凭同层就合并；真实尽端/分隔/跨层另记依据 |

检查实际完整可见线网，外环拓扑、总体连通、图层保留或总面数均不能替代本表。构造用的父矩形不是现实道路裁剪边；若它封住入口，按真实平台与路缘关系调整父面和共享边，删除假封口后重查相邻面。真实地面边界及有独立作用的分隔仍保留。

## 反馈重开与复检

蓝色等手绘批注用于定位问题和理解本轮意图，检查点及 expected 来自未标注原图。用户明确要求设计改线时另记设计期望，不冒称为原图现状；案例中的蓝色不成为固定语义。

用户推翻旧判断时，重开对应对象及受影响相邻接边，旧结论保留为 superseded；外环、建筑等未被反馈涉及且已核验的部分继续作回归基线。先在旧文件复现失败，再在修复文件及最终 DWG 回读上运行同一适用检查；新增绿地边引起停车/铺装共边变化也列入影响范围。

记录 `user_acceptance` 与 `native_sketchup`，与视觉/几何结果分开。`geometry_verified` 只覆盖该版本实际执行项，不能转写 `user_approved`；未做 SU 桌面导入、选面、推拉就写 `not_run`。几何通过不证明遮挡边精确还原。

相关错例：[EF002 内部覆盖](error-library/cases/EF002.md)、[EF011 绿地地面边](error-library/cases/EF011.md)。项目坐标、像素容差、路宽、面数及原始影像只留项目，不成为便携规则默认值。


## 同类反馈的优先检查

- 真实隔离带不自动拥有“外圈＋种植内圈”。先确定是否存在独立用途或用户要求的结构层；默认概括模式不保留无用途窄边。按整对象检查端部、中段同面和内部残线，参见 [EF007-B](error-library/cases/EF007.md#ef007-b)。
- 不规则花池也应有可信主轮廓。先检查尖钩、交替急折、细凹口、狭颈和拼接共边，再决定重构主形或局部切接；维持原图锚点、通道净宽与真实转角。少数点贴合和闭合通过不代替整圈形态判断，参见 [EF011-B/C](error-library/cases/EF011.md#ef011-b)。
- 外部参考仅帮助理解形体组织，不提供本场地位置、尺寸或边界真值。用户要求时可检索类似花池，优先看实际边缘而非植物冠幅；加载失败如实记录。不能把参考图当新设计覆盖原图，也不把每轮联网/Pinterest/其他技能设为必经步骤。
