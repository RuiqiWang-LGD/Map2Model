# CAD 分面模块：先外层，后内部

用于路网清楚、色块围合明显的正射图或简化平面图，尤其是大范围前期底图。目标按 [SU 前期平面合同](su-plan-contract.md) 定义：**连续同层道路独立成面，水面与每个主要父块保有完整边界，内部对象再形成各自面环**。主路/桥面内部不混入低层边，大水陆分界不留无独立用途的平行窄条。这是 CAD 内部的两个构造步骤，与前面的图像简化阶段区分。用户要求分步看成果时，在对应步骤交付并等待反馈；用户授权完整 CAD 时，自行完成两步，保存中间检查点，不额外索要批准。

## 模块合同

| 模块 | 输入 | 构造与输出 | 进入下一步的条件 |
|---|---|---|---|
| M0 证据与参数 | 原图/已接受分析图、尺度状态、设计范围 | 独立源侧对象/探针、同面组与异面关系、主路遮挡范围、水陆单边检查区、图框截边、变换和形体预算 | 清单来自图像判读，不能由待检 CAD 或构造 manifest 倒推应有面 |
| M1 外层 | M0 清单 | 连续主路与可见桥面、水域、简单完整父块外环、唯一共边及必要图框出口封边；保存 outer CAD、清单和报告 | 完整原始线网、源侧逐面对应、主路内部零干扰、边界唯一与形体规则化均通过 |
| M2 内部 | 通过的 M1 CAD、固定文件哈希、内部对象清单 | 先确定二三级道路及接入，再添加建筑、绿地、内院、场地、水体等子环；保留父块外围与一级道路 | 新环归属正确、边界关系合法；全图恢复的道路与 M1 相同，基线实体未变 |
| M3 交付 | M2 CAD，或用户只要 M1 的成果 | 真 DWG、回读 DXF、由回读几何绘制的检查图 | 转换前后实体一致；对回读文件重跑同一模块检查 |

用户明确接受的 M1 是保护基线；M2 发现外围确有错误时，按本轮授权范围返修 M1，记录新旧依据并重新检查，不能默默移动已接受边界。没有用户 SU 反馈时，只记录 CAD 检查通过。SU 操作留给用户，除非用户明确要求代理测试。

这些步骤可由 [CAD 自动执行](cad-automation.md) 的项目配方和执行器串联：先确认语义和参数，再构造实际环、检查、存阶段基线。已有明确对象清单时无需重新写通用构造和出图代码。

## M1：先让道路和大块外环成立

1. **先分层级，再提轮廓。** 识别主路围合的父块。块内的建筑、步道、院落、草地边线先不参与父块切分；同一父块可以包含多个内部环。不能把所有像素小面直接当最终街坊。真实支路、分隔带和出入口按作用保留；把内部尽端、停车通道并入父块必须有图像/用户依据。
2. **道路骨架规整。** 长直段拟合成一条直线，方向来自该路段自身；弯道采用少量连续弧段或受误差约束的折线，路口保持合理圆转与宽度。不要把整图强制正交，也不要照着抗锯齿像素描碎折线。道路两侧与大块边界协同确定，不能分别拟合后留下窄缝或叠边。
3. **每个父块先做一个简单完整外环。** 对多边形底图，优先单个原生闭合 LWPOLYLINE；凹角、显著转折和曲率变化处留点，直线内部冗余点删除。外环必须简单、共面、非零面积。它表达边界，不等于 CAD 的 BLOCK 编组；图层或编组本身不保证成面。
4. **图框是拓扑的一部分。** 源图被裁切的块应保留有长度的真实截边，简化前固定截边端点。仅一个顶点碰到图框不能冒充截边闭合。父环已有图框边的部分只写一次；剩余道路出口沿图框补 LINE。避免另加一整圈重复图框。所有实际交点必须落实成导出线段端点。
5. **道路由完整可见平面分区验证。** 对简单同层裁切场地，可计算图框减去父块的候选道路，再用独立源侧对象/同面探针确认其范围和连接，并与实际 CAD 原始线网的面对应。道路可因真实隔离形成多个连通部分，数量由场地证据决定；不能固定全图一张面。默认桥面占地裁除下层线后与全部可见边共同验证，不能排除桥层。图框外连接与真实跨层关系另记语义；详细多层请求按 SU 合同专门分支处理。

独立父环方案适用于父块之间有道路或明确间隔的场景。真正直接共边的相邻对象采用一次物理共边、节点化边链与两个语义面记录；不要为了让每个对象都成为独立实体而重复共边，也不要无依据强行缩出缝隙。这类复杂线网需等效的逐面对应检查，不能直接套下述独立环检查器。

## M2：在已通过的外层中加细节

先安排所属父块内的二三级道路及其入口，确认道路和父块关系后，执行 [建筑主体判断与异常轮廓规整](building-regularization.md)，再处理其周围细节。顺序遵循 [分级围合](hierarchy-and-regular-geometry.md)；可自动筛出可疑轮廓，但是否拆出铺装、如何恢复楼体仍依据源图。所有修改继续使用本模块的父/子环和完整道路回归条件。

1. 固定 M1 文件与哈希、单位、全部基线实体及父块 ID。每个新增对象记录 `id, role, parent, source, cad_selector`，`parent` 指唯一外层父块；需要多级内院关系时另记直接包含者和孔洞作用。
2. 建筑先恢复主要基底、朝向和凹口，再加有作用的绿地、内院、运动场、水面。背景用父块剩余面表达；建筑环已经形成背景孔洞时，不再复制一个几乎贴边的绿地孔洞环。保留源图真正的内院和通道。
3. 默认内部环之间**相离或完整包含**，同一层不交叉、不点碰、不贴重边；子环完整处于父环内且保留可辨间隔。包含关系是允许的几何关系，是否是内院、建筑覆盖草地或水面孔洞仍须记录语义，不由颜色猜定。
4. 对越界、贴边、像素碎角做局部简化或有依据的局部移动。优先清理病点，不因一个极短边就删除整个主要块；避免对全部建筑/绿地统一缩小或全图 buffer。必须保留的接触/共边走共享边模型，不能硬套间隔要求。
5. 复检**全部实际实体组成的图**。旧图层没变只证明未编辑旧对象；新增线仍可能进入道路、分割父块或生成微面。全图检查必须确认每个父环仍是某个实际面的完整外边界，内部对象对应独立面环，道路区域与 M1 一致。

## 参数：把贴合误差与封面条件分开

- 单位、比例、拟合偏差、最短边、最小净距均写入项目配置，不能沿用案例像素值。选择最短边/净距时参考源图精度、实际尺度及必须保留的最窄通道；大、中、小尺度使用不同细节预算。现有检查器的 `min_edge` 是硬几何阈值，应设在需保留真实短边以下；形体锯齿另查连续振荡和源图意义，不能为满足阈值删真实转角，也不能仅调阈值称锯齿已解决。
- 长直边用方向与法向偏差约束，曲线用弦高/曲率偏差控制分段；每个父块记录简化前后顶点数、短边数和最大边界偏差。少点是优化目标，完整外环与重要形状是约束。
- 若用户接受 3%–5% 的外形近似，应先明确度量。本流程可用逐对象对称差面积 `area(new △ source) / area(source)`，同时检查局部最大边界偏移；不能用全图面积作分母，或用净面积差抵消一增一减。阈值只用于拟合，不能豁免开环、重线、自交、断路。
- 合并内部通道或调整父子层级属于语义改动，单独记录前后关系与面积变化，不把它藏进简化误差。不要因为案例允许某个例外，给以后所有场地默认开豁免。
- 模糊图先减少不可靠细节、保住主路与父块结构，记录推定和待确认区域；规则不能提高图片本身的信息量，不宣称模糊图也能准确自动识别。

## 批量检查，不逐条手工描查

先建立图像侧的对象清单，再一次批量执行以下不变量。人工/Agent只看失败位置、低可信语义与若干代表性局部，仍需覆盖主路连通和主要外围的图像判读；无需逐一肉眼检查所有碎线。

| 检查层 | 必须成立 | 失败时返工范围 |
|---|---|---|
| 原生实体 | 必需对象齐全；Z=0；环原生闭合、无自交/零长；物理边无重叠；交点都是实际端点 | 对应对象及相邻接边 |
| 外层结构 | 父块互不相交；截边由边接框；图框覆盖恰好一次；短边满足项目阈值 | M1 对应父块/路段 |
| 原始线网 | 未经自动修补的原始线段 `polygonize_full` 无 cuts/dangles/invalid；覆盖图框 | 真实导出线段；修完重新导出 |
| 面与对象对应 | 每个父/子环恰好对应一个实际面的完整外边界，允许有子环孔洞；未认领面须由源侧证据确认为道路；独立同面/异面探针与完整边界均成立 | 对应层级及漏导/错分对象 |
| SU 平面合同补充门 | 主路内部无干扰边；水陆边无无作用平行窄条；形体无栅格台阶/短折线串/碎面。具体证据按 SU 合同，不自动声称由随附检查器完成 | 对应主路、岸界或异常形体 |
| 细节与回归 | 子环归属唯一、包含/相离且满足净距；M1 实体、单位不变；全图道路与 M1 相同 | M2 对应子环；外围变更须回 M1 |

总面数只作交叉核对，不能单独判通过。`unary_union`、`snap`、`buffer(0)` 等可以用于构造/修复候选，但不得先用它们修好线网再称原始 CAD 已通过。修复必须写入 CAD，随后重新读取未修补的实际实体。辅助布尔运算可用于量测/比较已提取面，不能替代原生线网检查。

## 可运行检查器

`scripts/check_face_hierarchy.py` 实现上述**矩形裁切、单层、独立多边形环**的几何检查。支持零宽、无 bulge 的闭合 LWPOLYLINE 以及沿图框补齐的 LINE；模型空间每个实体必须入清单，未知类型/未列实体失败。原生 ARC、CIRCLE、bulge、共边父块、开放参考线和非矩形边框不在此工具范围：保留合理曲线与共边设计，使用 `check_cad.py` 加项目中的等效曲线/边链检查，并如实记录本工具 not_run。不能默默弦化原生曲线来声称本工具已精确检查；若主动采用折线方案，应先约定几何偏差再导出。

```text
python "<Skill绝对目录>/scripts/check_face_hierarchy.py" work/process/outer.dxf --config work/outer-faces.json --report work/process/outer-faces-qa.json
python "<Skill绝对目录>/scripts/check_face_hierarchy.py" work/process/detail-roundtrip.dxf --config work/detail-faces.json --report work/process/detail-faces-qa.json
```

复制 [配置示例](../examples/face-hierarchy.json) 后，替换为本项目实测图框、参数和**实际导出 handle**；示例数值与编号不能直接用于地图。此配置独立于 `project.json`：

- `module`: `outer` 或 `detail`；`units` 是 DXF INSUNITS 整数，0 为未定单位，4 为 mm，仅表示工作单位，不自动证明物理尺度。
- `frame`: `[xmin,ymin,xmax,ymax]`；`parents`: `{id,handle,clipped}`，截边标记来自源图；`frame_handles` 仅列补齐图框的 LINE。
- `tolerances`: `coordinate` 为数值比较容差；`area` 为面积计算容差（平方绘图单位）；`min_edge` 为最短原生边；`min_clearance` 为子环与外围、其他子环边界间距。四项必须为有限正值，前者远小于需要保留的形状。这里的面积容差不是源图拟合的百分比。
- `expected_road_components`: 依据图像确定的道路面数量；`details`: `{id,handle,parent,role}`。外层步骤为空列表，内部步骤列出所有新增环；语义来源和直接内院包含关系另存对象清单。
- 内部步骤另加 `baseline: {"dxf":"process/accepted-outer.dxf","sha256":"该文件实际64位哈希"}`。相对路径基于配置文件目录；哈希、完整基线实体、当前新增实体清单都检查。

报告包含输入/配置哈希、几何问题、原始面数与残线、面对应和内部步骤的道路回归。返回码 0 为配置范围内几何通过，1 为几何失败，2 为配置/读取错误。报告默认拒绝覆盖，禁止覆盖输入/基线；只有明确替换旧报告时使用 `--overwrite`。

本工具不判读地图、不自动选择层级，不保证道路最窄处宽度、不检查源图拟合比例，也不证明 SU 已运行。其面配置来源仍需独立核对；它未实现 SU 合同的源侧同面组、近邻岸线多重性及形体规则化全部门。默认平面补跑 `check_visible_plan.py`，继续使用主检查器的源图锚点和视觉证据；仍超出工具范围的项补项目等效检查。对最终 DWG 回读文件执行，不能只检查构造内存或中间 DXF。

### 工具范围外的等效证据合同

原生曲线或真正共边网络没有随附的一键分面检查器；不以 `check_cad.py` 单独通过代替本模块。项目检查至少记录：实际实体及弧参数、端点/交点在实体上的落实、唯一物理共边与各父/子面边链对应、完整外环及孔洞关系、残线/重复/相交结果、完整道路区域与基线回归。输出 `process/face-equivalence.json`，逐项给出 `status, method, evidence, tolerance, affected_ids`，另记输入及基线哈希、检查脚本路径与运行命令。它是证据记录约定，不是现成 CLI 的配置。

等效检查同时纳入 [SU 合同各门](su-plan-contract.md#导出之后同时满足的门)，尤其从完整实际线网验证源侧预期，不以生成器输出的语义碎面作为唯一真值，不按图层豁免共面桥下线。

在本项目实现并运行对应检查后才填 pass。若以采样近似曲线做空间计算，必须报告弦高误差及其与所查最窄间隔的关系，同时独立检查原生弧端点/参数；采样结果本身不能证明原生曲线交点已打断。无法检验的项写 pending，保留候选状态或说明具体限制，不把工具 not_run 当作该项已通过。
