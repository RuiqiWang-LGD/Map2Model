# 文件保留与清理

## 项目命名与保存位置

默认层级为“主文件夹 → 项目子文件夹 → 成果 / 其他”。主文件夹就是用户给定父目录或系统实际桌面，不额外创建一个名为“主文件夹”的空壳。

新项目采用“场景主题＋项目用途”命名，默认 `<场景主题>项目_建模底图`。主题取资料中明确的主要地物或空间类型；地点只使用已知信息，不猜城市。用户指定名称或完整项目目录时沿用；续作不重复套层。

- 用户给父目录时，在其中创建项目文件夹；未指定时读取系统实际桌面位置，在桌面直接创建项目文件夹，不额外套 map2cad 或 outputs。无法读取桌面时说明，不猜路径。
- 新项目重名且不是续作时追加 `_02` 等序号；同项目修改采用版本号，不覆盖源资料或用户既有成果。
- 按实际内容创建目录，不预建空文件夹。用户只要求更新技能时，不创建示例项目、不清理既有项目。

## 默认交付：成果与图片两类

```text
场景主题项目_建模底图/
├─ 成果/
│  ├─ 场景主题_建模底图.dwg
│  └─ 场景主题_建模底图.skp
└─ 其他/
   ├─ 场景主题_二维平面.png
   └─ 场景主题_原图叠合.jpg
```

格式按任务实际范围提供：影像转 CAD 交付真实 DWG，已有 CAD → SU 交付真实 SKP，要求 CAD＋SU 时交付两者；缺少转换器才交付可编辑 DXF 并说明缺项，不为凑目录额外转换。最终二维图、原图叠合、确有用途的几何预览和原始参考图放入 `其他`；不复制同一图凑多份成果。纯 CAD/SU 任务不强制生图。

图像阶段已复核推荐稿也直接放 `其他`，文件名注明用途和版本，交接时给出链接。有设计范围时保留现状整理版与清空版两个用途版，均放这里，只主动推荐一张。默认只保留最终有效稿；被替代的初稿、失败稿、局部试改及重复预览在收尾时清理。用户指定保留的历史稿例外。旧图片与当前模型不同版时保留明确的历史版本标记，不改名冒充最新叠合；新任务的最终原图叠合仍必须来自最终 DWG 回读几何。

**提示词默认不交付、不永久保留。** 初始提示词、修改指令、元数据及版本关系在执行期间放外部 `work_root/process`；完成后按下节清理。仅当用户要求保留提示词或可重跑归档时，将所需内容放入 `其他`，不增设第三个顶层目录。用户直接要求提示词时，提示词本身就是成果，不删除。默认不生成文件导航、交付说明、检查报告、修改记录、压缩归档或 `99_过程存档` 作为第三类交付；必要使用限制在聊天中简短说明。

已有项目的成果及图片目录名称可沿用。只有用户要求整理该项目时才迁移、清理它，不因更新技能批量处理其他项目。

## 外部任务工作目录

**交付目录与运行目录从开始就分开。** 用户项目目录从运行第一步起只接收已复核的推荐图或正式交付文件，不在其中生成提示词、脚本、草稿、配置、日志、检查报告、转换中间文件或自动备份，也不创建 process、临时目录或指向外部缓存的链接。仅用户明确要求保留的提示词或归档可作为交付内容放入“其他”。

开工先解析两个绝对路径：`delivery_root` 是用户的项目子文件夹，`work_root` 是本次任务的外部工作目录。优先使用当前 Codex 任务实际工作区下的 `.map2cad-work/<项目主题>-<交付路径短哈希>/<任务ID或唯一运行ID>/`；这是本技能的工作目录约定，不是对 Codex 固定安装位置的假设。同项目续跑使用原目录，新任务或同名异址项目使用独立目录。

创建前解析真实路径并检查包含关系：工作目录必须在交付目录之外，不能通过符号链接或目录连接落回其中。如果当前 Codex 工作区位于交付目录内部（或就是交付目录）、不可写或无法确认，就选已知可写且在交付目录外的 Codex 工作区；没有合适工作区时使用系统实际临时根目录下的 `codex-map2cad/<项目标识>/<运行ID>/`。优先完成可用外部目录的选择；都不可用才说明阻碍，不能静默退回交付目录。不要把运行材料写入 Codex 的配置、技能安装目录或其他任务目录。

在外部工作目录内部保存源资料关联、交付目录、选定版本和续跑状态；交付目录不放导航或工作目录指针。源资料以原位置只读访问；工具需要本地副本时复制到外部工作目录并维护路径/哈希关联。移动配置时重算相对路径或改成绝对路径，源图、基线和回读依赖不得失联。

本技能各页的“过程目录”、`process/...` 均指 `work_root/process/...`；命令中的 `work/...` 是外部 `work_root` 的路径占位，执行前替换为实际绝对路径并正确加引号，不能在交付目录下建立名为 work 的子文件夹。`<Skill绝对目录>/scripts/...` 须替换为实际安装脚本路径；从外部工作目录启动脚本，不为运行脚本把输入输出放进技能目录。复制示例配置到外部工作目录，`output_dir`、`--output`、`--output-dir`、报告路径、可配置的工具工作目录和缓存/临时目录都指向外部工作范围。DWG/SKP 也先在此生成和回读，转换器随产的 metadata、BAK 和日志不会进入交付目录；只将已验证的目标文件逐个复制到“成果”或“其他”，不整目录复制。

等待选图、修复或继续转换时保持外部任务目录以便续跑；最终核对后按本页清理规则删除无依赖文件。中断或失败不自动删除续跑依据，不仅因旧缓存较早就清扫其他任务。用户自行打开和编辑交付文件时由软件产生的文件，不属于技能可以擅自改变的全局软件设置。

## 执行期间与清理触发

检查、配准、转换、回读、复核和续跑材料统一在外部 `work_root/process` 生成。精简交付不减少生成和验收步骤：实际检查仍要做，pending 不得写成 pass。最终成果已保存、回读核对完成、没有运行任务或后续依赖时，清理本次生成且已无用途的过程材料；等待选图、后续转换、修复或用户要求的分阶段验收时先保留。用户明确要求清理已有项目时按其指定范围执行，清理本身不代表模型质量或用户验收已通过。

执行与验证期间记录源图、选定稿、最终文件哈希、配准变换和真实检查状态。默认不为追溯而另建永久记录包：收尾时在当前任务记录中说明保留/删除范围、完成情况及必要限制即可。需要可重跑归档时才保留完整依赖；已清理的检查输入不能声称仍可重跑，后续修改须重新建立实际检查。

错例维护已获授权时，在清理前同步确有复用价值的增量；未获授权或不可写时，说明未合并状态，不为可选错例归档强制增加用户交付目录。仍影响当前修复或明确待办的证据属于依赖，暂不删除。

## 范围与执行安全

只清理本任务确认生成、已无依赖的临时副本、旧候选、提示词、配置、脚本、日志、检查 JSON、转换 DXF 和自动备份；不按扩展名扫描全盘，不把用户原始脚本、JSON、DXF 当垃圾。保护源 CAD、唯一原图、当前成果、用户手动修改文件、指定历史稿与其他项目。保留的参考原图不因还有外部副本就强制删除。

先列明保留与删除清单，核对保留文件可读；解析全部目标绝对路径，确认处于本次任务已核对的外部工作范围内；只有用户明确要求整理既有项目时，才按该项目的单独清单清理历史过程文件，不跨符号链接或目录连接。逐文件执行，只有确认目录为空才删除目录。操作前后核对保留成果哈希，预检路径错误立即停止并修正后重检；执行成功前不写已清理。保留文件中的旧导航或索引若引用已删除内容，应一并删除或更新，不能留下虚假有效引用。

用户已授权本任务范围时继续执行，不重复确认；当前项目的删除授权不扩展到其他项目。技能更新仅改变后续输出方式，不自动授权扫描删除历史资料。

## 已有授权与审批恢复

自动审批拒绝时保留未删对象并说明具体原因。新增明确授权可按同一清单再次提交；仍拒绝则报告阻碍，不通过换 shell、拆命令或扩大范围绕过审批。没有权限时如实说明未完成部分。
