# 第一阶段：从源图整理简化二维图

**片区模式优先入口：** 片区范围先执行 [完整块面与一二级道路最高优先级规则](district-priority.md)，再应用下文于实际保留对象；下文“二三级道路/内路/全部建筑”不扩大片区保留清单。场地详图模式及明确局部详图区保持原细节规则。

## 默认完整交付与按需分步

[复杂城市](complex-urban-two-stage.md) 与 [低清晰度输入](low-clarity-reconstruction.md) 默认 review_stage=complete，内部先检查道路/块面并固定，再加二三级道路与细节，完成后推荐一张完整稿，不自动要求用户先审结构。用户明确分步或关键结构经自查仍需用户决定时才采用按需分步：urban_structure 选独立模板且不启用细节模块；结构实际通过后 urban_detail 绑定基线和用户记录。局部关键问题可以只展示局部证据，不必全图重做结构稿。已经明确取消旧阶段等待则记录覆盖依据，按 complete 继续，不伪造通过意见。图像到 CAD 的版本选择仍继承原规则和已有授权。

下文“逐字保留通用正文”指脚本为本阶段选择的模板；urban_structure 使用 urban-structure.txt；其余阶段按 processing_mode 选择：片区结构模式使用 district-structure.txt，场地详图模式使用 simplify-map.txt。无模式字段的旧配置保留旧模板兼容；新项目先判断并填写模式，不能将两篇拼接造成保留建筑与禁止建筑的冲突。


## 先引导输入，再准备提示词



收到场地图后先查看图片与已有说明，分清原图、辅助图、风格图和旧成果。已有简化图可进入验收；用户明确直接转 CAD 或局部修改时，按对应路径执行。



对尚待简化的原图，用一条独立的普通聊天回复引导用户补充条件，不使用弹出式问答工具。首次只列三项：**1．建议处理模式；2．尺度参照；3．设计范围**，末尾用自然段说明如何回复及后续动作，不设第四项、不询问或推荐外部平台生图路径。已有答案直接沿用；用户已提供完整条件、说明未知或要求开始时直接执行，不为模板重复提问或等待。

第一项按 [模式判断规则](processing-modes.md) 给出推荐、具体图像依据与主要取舍。主体适合详图但局部细碎时，在同一项指出需要概括的位置与限制，不因局部模糊将全图降级。

尺度参照只问缺失的对象、位置/两端、数值、单位和测量含义。可用道路横向宽度、建筑地面基底边长或场地边长；不能将倾斜屋顶作地面标尺。未知尺寸可按相对尺度继续，位置有歧义时暂不据此定标。

设计范围可文字说明或在原图副本上涂色标注，保留未标注原图。指定范围时另备范围内仅留道路的清空版；无范围只整理全图现状，不猜范围。详见 [设计范围与成果版本](design-scope.md)。

需要用户补充时用自然收尾，不附“本轮先收集条件，依据你调用的技能”等规则说明。更高层级明确要求披露时按其要求执行。用户回复“先整理全图”即按相对尺度、无设计清空范围继续内置生成；不追问执行路径。

首次引导示例（庭院俯视图；其他图片重新判断模式和图像依据，已有条件不重复索要）：

> 1. **建议使用场地详图模式**：这张庭院俯视图的园路、绿地和中央曲线景观比较清楚，适合保留主要轮廓、内部步道及可辨设施；树冠纹理省略，遮挡处适当概括。
>
> 2. **尺度参照**：有没有一处已知尺寸？例如庭院内边界的宽度，或某段园路的宽度。说明具体位置和尺寸即可；暂时不知道，也可以先按相对尺度整理。
>
> 3. **设计范围**：这次是整理全图现状，还是有准备重新设计的区域？可以直接描述，也可以在原图上涂色标出。指定设计范围后，我会另备一张范围内仅保留道路、其余清空的版本。
>
> 你把已知尺寸和范围告诉我就好，也可以发一张标注图。暂时都没有的话，回复“先整理全图”，我就开始生成简化平面，并对照原图检查、调整，再把转 CAD 推荐稿给你看。

## 自动合成通用框架与当前项目条件



不要逐段重写 [详图提示词](../prompts/simplify-map.txt) 或 [片区提示词](../prompts/district-structure.txt)。模型查看图片后只整理项目事实和场景判断，脚本负责按模式及阶段选择模板、校验并合成完整提示词：



1. 把 [提示词项目示例](../examples/prompt-project.json) 复制到外部任务工作目录的 `process` 子目录，命名为 `prompt-project.json`。先填写 processing_mode 和 mode_reason，存在明确授权局部详图区时填写 detail_scope；再填写源图类型、设计范围、尺度、必留/省略对象、输出范围、图片角色、补充条件和推定项。未知尺寸使用 `scale.status: relative`；未知设计范围删除该字段，不能填入猜测内容。详细字段见 [项目设置](project-contract.md#提示词自动化配置)。

2. 查看源图后选择少量确实适用的场景模块。运行 `python -X utf8 scripts/build_prompt.py --list-modules` 查看模块；当前提供倾斜建筑、密集建筑、滨水、田地和场地细节五类。模块是强化提醒，不负责识别图片，也不能代替项目事实。未出现的场景不选；同一模块重复填写会自动去重。

3. 在外部任务工作目录运行；将脚本和输入输出占位替换为实际绝对路径：



   ```powershell

   python -X utf8 "<Skill绝对目录>/scripts/build_prompt.py" --input "外部工作目录\process\prompt-project.json" --output "外部工作目录\process\simplify-map.project.txt"

   ```



4. 脚本只替换模板中的“输入与可选项目条件”，其余通用正文逐字保留。它同时生成 `simplify-map.project.meta.json`，记录源图尺寸和哈希、模板及场景模块文件哈希、所选模块及提示词哈希。出现未知字段、未知模块、冲突尺度、缺图或模板标记异常时停止，不留下半份成果。

5. 快速查看生成文件的项目条件段，确认用户明确条件和模型推定分栏正确、所选模块符合图片及处理模式。片区模板只对保留对象与授权局部详图区应用细节模块，不补造模糊小建筑。无需重新审读整篇固定正文；模板本身发生修改时才进行完整复核。



把 `simplify-map.project.txt` 的**完整内容**传给内置生图，不能只给差异、模块名或“遵循之前规则”。图像附件和工具必需参数另行传入，不改写提示词语义。提示词作为执行期间的内部生成与追溯材料暂存，完成后默认清理，不主动交付外部平台使用说明。



脚本不可用时才手动替换模板中两个标记之间的项目条件，并保持标记外正文不变。执行内置生图时，把完整提示词保存为文件并传给工具；正式交接不主动粘贴长提示词；仅用户要求保留时作为可选成果提供文件链接。每次调用只生成一张图并保留原图；无设计范围准备现状整理版，有设计范围按 [双版本流程](design-scope.md) 先复核现状整理版，再以它为基线局部生成清空版，脚本拒绝覆盖既有提示词或元数据，后续修改须使用新的输出文件名另存版本，并记录其对应生成图。



用户另行明确只要求提示词时，按该请求交付，不自动生图；这不恢复初次引导中的外部平台选项。



## 执行内置生图

条件已明确，或用户说明未知、要求先整理时，直接检查当前可用的内置图像工具，传入已查看的源图和完整项目提示词执行，不再要求选择路径。按当前工具及用户已给授权执行；不因内置工具不可用而自动切换密钥 API、收费接口或外部插件。

若内置工具不可用，保留已准备的项目条件和提示词，简短说明实际阻碍；继续可独立完成的准备工作。不主动要求用户去其他平台生成再回传，也不虚构已生成图像。

内置生图的初版、局部修正版和复核材料执行中暂存外部任务工作目录，保留版本关系；推荐交接前把已复核推荐稿与另一最终用途版放入 `其他`，其余各轮图、复核与续跑材料仍暂存 process，完成后默认清理；项目根目录按 [项目命名与保存位置](output-lifecycle.md#项目命名与保存位置) 确定。先完成内部复核与必要修正，再只主动提供一张推荐稿。无设计范围推荐现状整理版；有设计范围仍准备现状整理版、设计范围清空版两个用途版本，按用户用途推荐其中一张，另一张留作备选，不自动并排展示。目录和完成后清理见 [文件保留与清理](output-lifecycle.md)。初稿、返修前图和中间候选不调用用户展示接口、不嵌入聊天、不打开用户预览面板；只用内部图像读取能力复核。用户明确要求看过程时才展示相应过程图。



调用前检查所用工具是否支持返回文件而不自动向用户显示；有此能力时使用。若预览由工具强制显示且没有关闭参数，技能无法隐藏已发生的界面行为：不虚构静默开关、不承诺完全隐藏、不再额外展示相同中间图。必要时简短说明“这个生图工具会自动显示预览，最终图会在复核后统一提供”，继续已授权的内置路径；不擅自改用收费接口。最终只主动提供一张复核后的推荐稿；不要为了履行展示步骤再次重复渲染工具已显示的图。用内部读取能力检查局部，检查图不主动嵌入聊天。



收到图像后，先在外部任务工作目录保存原图路径、项目提示词及生成结果的关联，再实际查看、比对。位置和尺度检查在此阶段执行，不以“提示词里已经写了”代替验收。



发现问题采用局部修正及原图再核对，保留已正确部分；不能反复全图生成导致位置漂移。默认连续两次相同问题仍未改善时，保留最佳候选，把对应区域转入 CAD 局部处理队列，不无限生图消耗时间。



工具入口名称不等于底层模型名称；不能因为没有 image2 MCP 而声称内置 image_gen 使用另一模型。正常回复用“开始生成简化平面”等自然表达；除非发生影响交付的能力限制，不播报工具路由。



## 本阶段就执行的位置和尺度检查

先执行 [明显地物定位与相对宽度检查](source-reference-lock.md)。清楚河岸、上下游弯段、洲岛端部和桥头须在原图建立独立参照；道路与当地河宽等参照物按同一相对尺度核查。可调透明度叠图只作如实对照，不以局部拉伸掩盖偏差；当前失败不能以“后续 CAD 会修”改记定位通过。



1. 检查画幅、方向和完整范围。尺寸不同可以按相同宽高比做显示对应，不能擅自旋转或裁切。

2. 从原图独立挑选分散于画面的稳定地面锚点：路口、桥头、平台转角、河岸转折等。避开倾斜高楼屋顶、树冠、阴影及水花。记录原图与分析图对应位置及来源。

3. 逐点比较，并看锚点之间道路和地块是否漂移。显示缩放必须一致。明显局部漂移不能用整图弹性拉伸掩盖；改对应图像对象或给CAD阶段明确原图控制点。

4. 已知宽度对象检查起点、中部、终点在法向上的相对宽度，桥头与桥身关系一致。这里检查生成比例是否合理；单幅影像标尺不足以证明全图实际尺寸精确。

5. 如果做了真实像素测量，记录测量方法、图像分辨率、容差来源与残差；只有视觉看图时写“视觉复核”，不得编造像素误差或米制精度。



## 图像验收顺序

urban_structure 阶段只验主要道路、水域、桥面和中性父块的范围/连接/定位，并检查建筑、绿化和内部细节是否误入；下表建筑平面化、建筑浅灰与绿色植被等项标为本阶段不适用，不能为满足表格补回细节。第二步再恢复相应内部对象检查。


| 检查 | 通过条件 | 不通过时 |

|---|---|---|

| 分类辨识 | 连续深灰路面、浅灰建筑、同蓝水面和同绿植被 | 修正填色/纹理，不加粗全部描边 |

| 路网逐条追踪 | 必要路段有实际宽度接续；真实尽端与分层有解释 | 先补合理道路，再调整建筑 |

| 主要场地外围 | 能沿有依据的外缘追踪，入口和截框关系清楚 | 修主外围，再补内部块 |

| 倾斜建筑（共用） | 无立面，严重投影不沿用拉长外包络；大尺度允许有依据的街坊组团概括 | 按原有分区/组团方法结合地面关系修正，不新增全图逐栋精修门 |
| 中小尺度场地详图（限定分支） | 全部可辨建筑逐栋检查接地位置、单一基底与伪立面残留 | 执行 [二维基底门](building-regularization.md#中小尺度建筑的二维基底门)，局部修正后再推荐；不将此逐栋门推广到大尺度 |

| 水域和岸上分区 | 水花条带省略、可见桥面完整；大水陆界唯一，无独立用途的岸顶岸脚窄条省略；明确详细请求优先 | 删除假路与无作用窄条、裁去透入桥面的下层线，保留真实有用对象 |

| 原图位置和比例 | 主要地面锚点及其间走向无明显漂移 | 定位问题区局部修复/转入CAD修复队列 |



审查输出在执行与续跑期间留在过程目录：当前原图与分析图、`image_review.md`、独立锚点表、未解决问题清单。写明检查者、图像文件哈希、查看范围、通过/失败/待查和对应证据。用于当前图像的通过记录不能直接给另一张生成图使用。最终任务验收并核对保存后，按 [文件保留与清理](output-lifecycle.md) 清理已无依赖的内部材料，默认不另建永久修改记录；等待选版或转 CAD 时仍保留。



## 交接到 CAD



### Codex 内置生成的图：选择推进版本



内置生成图完成复核与必要修改后，先将一张推荐稿实际保存到项目的 `其他`，其他过程修改稿暂存 process，最终按清理规则处理。推荐依据是当前尺度分支下的源图空间关系与转 CAD 可用性，不一定是最后生成的那张。中小尺度场地详图须完成新增逐栋二维基底门；大尺度按既有分区/组团方法评估，不以这道新增门阻断整图交接。所有尺度仍执行原有道路连续、严重投影及主要位置检查，未通过的对应项目不能写成通过。用普通聊天简短交接，不使用弹出式问答、不逐轮讲内部修图过程，用户测试/审查技能或要求看过程时再展开。只说保存成功后已核实的路径。



可用话术：“推荐稿〈版本/文件名〉已放入目标文件夹，请查看。是否用这张图继续转 CAD？”用户需要比较过程稿时再提供对应链接，也可以指定另一张或说明修改位置。当前本地文件可读时不要求重复拖图。



- **有设计范围**：仍准备两张用途版本，默认按已声明的清空设计用途推荐清空版，用户用途指向保留现状时推荐现状版。只主动提供推荐的一张，用一句话说明另一版的位置和区别。推荐项明确时，用户回答“同意/是”即选定该稿并授权转换；推荐不明确且同时存在两个待选项时才补问版本。

- **无设计范围**：只提供一张已保存的现状推荐稿及下一步确认；回答是后直接转换，要求修改则局部修正，回答否则暂不转换。

- **已明确选定图并要求转换**：直接锁定版本、路径、哈希和处理方式，不强制重做两版、不再选图。

- **要求修改**：修改对应版本并复核。若现状版改动涉及保留道路、范围外或未标注孔洞，同步局部更新清空版，更新基线路径/哈希及对应提示词元数据；只改动将被清除的内容时，复核无影响后可沿用清空图，但仍记录新版基线关联。不得把未修改旧稿充当最终现状整理版，也不为同步而全图重生。



有设计范围但两版尚未齐全时，如实说明缺项，不能把初稿充作第二选项。用户已明确只要某一版时按该请求处理。选定清空版后将清空范围与已授权删除记录交给 CAD，防止后续按原图恢复非道路对象。



### 外部平台回传或直接导入的图：按意图直接转换



用户自行带来外部生成图或已有简化图并要求转 CAD 时，不重复询问“是否用这张图转 CAD”。先复核，再按其转换请求执行。



若发现具体问题并拟提出可选改进，用普通回复说明位置、后续影响和拟改内容，询问是否采用，等待用户选择。例如：



> 这张图的桥头道路有一处窄缝，转 CAD 后可能分成两块。我建议先接通这里，其他部分沿用原图。是否采用这项修改？回复“是”先修改再转 CAD；回复“否”就按当前图直接转换。



此分支的“否”表示不采纳建议，**仍按当前外部图开始转换**，与内置生成确认的“否”含义不同。不得把否定修改当作取消转换，也不得偷偷实施被拒绝的改动；拒绝项记录为 accepted_limitation，保留必要的格式、闭合及拓扑整理并如实报告源图限制。没有实际修改建议时直接转换，不为走流程凑一个问题。用户只是分享图片、尚未表达转换意图时，不自行开始 CAD。



### 交接证据



交接包保存 `processing_mode`、模式依据/选择来源、`detail_scope`、保留/概括/省略待补清单，以及 `selected_variant`（existing_condition / design_clear）、选定图路径/哈希、范围图路径/哈希、与现状整理版的对应关系及已授权清除记录。这些是过程记录，不直接添加到不支持它们的 CAD 检查配置中。交接包必须能回答：哪些是已确认边界，哪些是推定道路/基底，哪些问题仍待修；已知尺寸测哪条对象；设计范围在哪里。首阶段 pending 不等于任务失败。仅中小尺度场地详图的逐栋伪立面或基底偏移适用新增二维基底门，不能仅列 pending 就交作推荐稿；用户明确接受带限制候选后再推进。大尺度沿用原有交接和局部纠错队列，不附加逐栋图像确认要求。任何分支的待处理问题都须在 CAD 阶段落实，不能在总体验收中静默跳过。



生成图是栅格候选。即使看起来连通也仍需测 CAD 连接、宽度和重线；即使图像不完美，可靠源图证据可支持局部修复，不必为了微小问题反复全图生成。
